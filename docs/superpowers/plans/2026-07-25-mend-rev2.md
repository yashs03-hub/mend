# Mend Implementation Plan — rev 2

> Supersedes `2026-07-23-mend.md`. Rev 2 folds in real-device ingestion, real outbound
> telephony, the engine-as-webhook-tool architecture, and trend-based escalation.

**Goal:** Ship a demoable voice-first post-op ortho recovery co-pilot that fuses spoken
check-ins with objective vitals from real consumer devices through a deterministic clinical
safety engine. Juno x Anthropic hackathon, 25–26 Jul 2026.

**Tech Stack:** Next.js (App Router, TypeScript strict), Tailwind, Vitest, Zod,
@supabase/supabase-js, @anthropic-ai/sdk, twilio, ElevenLabs Agents (Twilio outbound +
webhook tools), Web Bluetooth. Deploy on Vercel. Node 22.

## Global Constraints

- Synthetic / anonymised patient data ONLY. Real device readings belong to the demo
  operator, never to a real patient, and must be labelled as the operator's own.
- Educational prototype. Every user-facing surface shows a "not medical advice" disclaimer.
- Market = United States. Terminology: ER, 911, care team / surgeon's office, nurse line.
  No NHS terms.
- **The LLM NEVER makes an escalation decision.** Only `evaluate()` in the red-flag engine
  returns green/amber/red. Claude extracts, transcribes, parses documents and writes prose.
- Fail-safe direction is ALWAYS toward escalation: on ambiguity, missing or poor-quality
  vitals, fall back to symptom-only rules — never reassure on uncertainty.
- Mend does not interpret raw ECG waveform. It consumes the FDA-cleared determination
  emitted by the KardiaMobile 6L and treats it as an input, never re-deriving it.
- Hero procedure = hip arthroplasty (elective THR + hip-fracture hemiarthroplasty).
  Persona = ~82-year-old post-hip-fracture hemiarthroplasty patient, POD 4, living alone.
- Every clinical threshold carries a `source` string naming its provenance.
- TypeScript strict mode. No `any` in `lib/clinical/**`.

## Device reality (binding — do not "improve" these)

| Signal | Source | Path |
|---|---|---|
| Heart rate (live) | Polar Pacer Pro / Garmin Vivoactive 5 | Web Bluetooth, standard GATT Heart Rate Service `0x180D` / `0x2A37`. Brand-agnostic — no vendor code. |
| ECG determination | KardiaMobile 6L | PDF export from Kardia app → upload → Claude document extraction. **Direct BLE is impossible** (vendor characteristics require an encrypted OS-level bond; ATT error 5). Do not attempt BLE. |
| SpO2 | Garmin Vivoactive 5 | Manual entry. Not exposed over BLE broadcast. |
| Blood pressure, temperature | Any home device | Manual entry. |
| Historical trend data | Seeded fixtures | Synthetic series in the shape real exports produce. |

### Task 5: Trend engine

**Files:** Create `lib/clinical/trends.ts`, `lib/clinical/trends.test.ts`.

**Produces:** `evaluateTrends(history: VitalsReading[], symptoms: Symptoms[], phase: Phase): TrendFinding[]`

This is the feature no threshold-based triage bot has: escalation on *trajectory*, where
no single reading breaches any threshold.

- [ ] **Step 1: Failing test.** Cases:
  - Resting HR 72 → 76 → 81 → 86 over four days, every value inside the envelope →
    one amber finding, metric `hr`, describing the rise.
  - SpO2 97 → 96 → 94 → 93, all above `spo2Min` → one amber finding.
  - Pain score 3 → 5 → 7 while the phase expects improvement → one amber finding.
  - Flat, normal series → empty array.
  - Fewer than 3 readings → empty array (insufficient data, never guess).

- [ ] **Step 2: Run — expect FAIL.**

- [ ] **Step 3: Implement.** Least-squares slope per metric over the trailing window
  (max 7 readings, min 3). Thresholds — this list is exhaustive and binding:
  HR slope ≥ +3 bpm/day → amber; SpO2 slope ≤ −1 %/day → amber;
  painScore slope ≥ +1/day → amber; tempC slope ≥ +0.15 °C/day → amber.
  The temperature rule is authorised: `TrendFinding.metric` includes `tempC`, a steadily
  climbing temperature inside the normal envelope is the characteristic early signature of
  a developing deep infection, and no single-reading threshold can see it. Its figure is
  engineering judgment and is recorded as UNCITED in `docs/clinical-decisions.md`.

  Each finding carries a stable `id` and a human-readable `description` naming the values
  and the window. Trends produce findings only — **they never return a `Decision`.**
  Composition with `evaluate()` happens in Task 12.

- [ ] **Step 3b: `phase` must be used, not merely accepted.** An accepted-but-unread
  parameter misleads every caller into believing phase context is applied. Use it to add
  **projected breach** to each finding: given the fitted slope and the phase's
  `normalEnvelope`, compute how many days until the metric crosses its envelope bound and
  append it to the description — e.g. "at this rate she crosses the day-4 expected maximum
  of 110 bpm in 2 days". Omit the projection when the slope points away from the bound or
  the crossing is beyond the visible horizon. This is what makes a trend finding
  actionable rather than merely observational.

- [ ] **Step 4: Run — expect PASS. Commit** `feat(clinical): trajectory-based trend engine`.

### Task 11: `/api/triage` — the ElevenLabs webhook tool

**Files:** Create `app/api/triage/route.ts`, `app/api/triage/route.test.ts`.

This is the architectural centrepiece. The voice agent calls this **mid-conversation** as a
webhook tool. The deterministic engine decides; the agent reads out the decision it is
handed.

POST body: `{ symptoms: Symptoms, dayPostOp?: number }`. The route loads the latest vitals
and ECG for the demo patient from Supabase (falling back to fixtures when empty), runs
`evaluate()`, and returns:

```json
{
  "severity": "red",
  "condition": "Suspected pulmonary embolism",
  "script": "Margaret, I need you to hang up and call 911 now...",
  "reason": "SpO2 91% with heart rate 122, post-op day 4"
}
```

`script` is the exact sentence the agent must speak — **generated from the Decision by a
pure function, not by an LLM.** Create `lib/clinical/scripts.ts` mapping each
`(level, condition)` to patient-facing wording at a reading age suitable for an
82-year-old: short sentences, no jargon, one instruction at a time.

Authenticate with a shared secret from `TRIAGE_WEBHOOK_SECRET` compared in constant time
against a request header. Respond within 3 seconds or the agent stalls mid-call.

Tests: red symptoms yield a red severity and a script containing "911"; green yields a
reassuring script; a missing or wrong secret returns 401; a malformed body returns 400
without throwing.

### Task 16: Design system foundation

**Files:** Create `app/globals.css` (rewrite), `lib/ui/severity.ts`,

**Typography — the governing rule: serif for the human voice, sans for machine data.**
- Display serif: `Instrument Serif` via `next/font/google`, used for page headings, the
  plain-language summary, what Mend said, and SBAR prose. Never below 20px.
- UI sans: `Inter` via `next/font/google` with `font-variant-numeric: tabular-nums`
  applied to every numeric readout — vitals, timestamps, trend values, rule ids.
- Body minimum 17px. Family view minimum 19px. Line height ≥ 1.5.

**Colour — "grayscale until it matters."**
- Surface `#FDFCFA` (warm paper), raised `#FFFFFF`, border `#E7E2DC`.
- Ink `#1C1917` primary, `#57534E` secondary. No pure black, no pure white.
- **There is no brand accent colour.** The only saturated colours in the product are the
  three severity tokens. If a screen needs a colour that is not a severity, it is wrong.
- Severity tokens in `lib/ui/severity.ts`, each carrying `{ fg, bg, border, icon, label }`:
  - green — fg `#15803D`, bg `#F0FDF4`, icon `CheckCircle2`, label `"On track"`
  - amber — fg `#B45309`, bg `#FFFBEB`, icon `AlertTriangle`, label `"Needs attention today"`
  - red — fg `#B91C1C`, bg `#FEF2F2`, icon `AlertOctagon`, label `"Urgent"`

**Accessibility — binding, not aspirational.**
- All text meets WCAG AA contrast against its own background.
- **Severity is NEVER communicated by colour alone.** Every severity rendering shows the
  icon and the text label too. This is both an a11y requirement and insurance against a
  venue projector washing out colour.
- Interactive targets ≥ 44×44px. Visible focus rings. `prefers-reduced-motion` respected
  in every Framer Motion transition.
- Vitals carry `aria-label`s that read naturally ("heart rate 122 beats per minute, above
  the expected range").

- [ ] Include a `lib/ui/severity.test.ts` asserting every severity token exposes a
  non-empty icon and label, so a future edit cannot reintroduce colour-only signalling.
